## 1. 总裁决

**保留课程使命与六类能力，撤回现有“最小教学栈已成立”的结论；否决把五个新假设一起建设成课程生产系统。**

项目的主要风险已经从“缺少知识依据”转向“没有足够的课堂成本与学习迁移证据，却继续增加设计层”。47 项研究目录可以保留，但不应继续产生学生端覆盖义务。新问题的定义应是：在已知学生基础和真实课时内，怎样用少量成熟材料，让学生反复完成观察、制作、修改和迁移，并让教师能够承担备课与反馈？

建议的最简结构是：**一条成熟资产主线 + 一个陌生载体的小型迁移检查 + 按需理论补注 + 一份六行成效检查表。** 这也需要试教验证，并非新的“全局最优”宣告。

“连续作品”不意味着八周只有一个对象。全程只做同一资产，容易把对案例的熟练误当成迁移能力；每节更换资产又增加负担。主资产负责积累，一个第二载体负责检验泛化，两者各有必要。

## 3. 六类 LO 保留，但修改其承重部分

| LO | 必须保留的可观察证据 | 应解除的过度绑定 |
| --- | --- | --- |
| LO1 | 从参考提出具体外观意图，解释主要材料、尺度、加工及使用痕迹；有理由地取舍细节。 | 不要求所有作品都讲复杂年代故事、做大型情绪板或走做旧工业资产美学。 |
| LO2 | 先预测，再改变一个因素并解释结果；能区分材质、光照、几何与显示条件造成的变化。 | 不把术语背诵或常见故障清单当成全部因果理解；“定性直方图关系”需澄清含义，不能当能量守恒验收标准。 |
| LO3 | 按新要求修改指定区域和相关通道，保存可继续编辑的结构，并验证非目标区域。 | 不强制某种 UI 或特定生成器；“图层之外都是破坏性制作”不成立。 |
| LO4 | 能解释一个小型程序的输入与输出，自己修改一段逻辑，控制有意义参数，并在另一尺度/载体上检查变体。 | 不能只拉教师做好的滑块；也不必为证明程序化而学习完整 Designer。 |
| LO5 | 针对需求选择输入来源，实际检查一份生成/转换结果，作出修复、替换或拒绝的决定。 | 不要求每个劣质输入都必须救回；去光照不是唯一正确路径，也不能把推测出的贴图当真实测量。 |
| LO6 | 在改变观察条件后复核，并按一份明确交付约束打开、检查交付件。 | 不强制双完整管线，也不能用切换 EEVEE/Cycles 冒充完成外部交付。 |

“受控”必须定义在数据和任务层面。若改变掉漆范围，暴露出的金属反射当然可能变化；不应要求物理上相关的结果冻结。保持的是非目标区域和明确指定的不变量，而非全图像素绝对一致。

同样，“换灯后还好看”是弱标准。粗糙与光滑表面在新灯光下本就应有不同响应。应检查变化是否符合预测、材质辨识与意图是否仍成立。诊断时先控制变量，最后再做综合环境变化，避免把多个变化混在一起而无法归因。

## 4. 教材与成熟实践主线：允许有界重开，不再全网重选

**已有研究投入不是保留 Shah 的理由；已有材料的可复用程度才是。** 既有来源索引确认 Shah 提供预制资产、Painter 图层与遮罩实践，且在参数暴露、物理原理等方面存在边界（`source-native-knowledge-index.md:461` 起）。这些已知事实足以支持有限比较，不需要重做 47 项来源研究。

本次应比较三条路线，而非新增一个庞大候选池：

1. Shah 的一段连贯 Painter 实践 + Blender 观察/程序化补充。它保有现成讲解与资产，但有双宿主、版本修订和许可成本。
2. Blender Fundamentals 的 Watering Can 材质—灯光段作为资产主线，缺口只补受控局部编辑、生成结果判断和交付。它更接近软件最少偏好，但不能假设该段已覆盖课程核心。
3. 一个连贯的第三方 Blender 材质/贴图课程片段作为替代候选。CG Cookie CORE V2 官方页面确有 5.2 LTS 学习路径及 Shading 课程；这是值得抽查的线索，不是已获验证的推荐采购。[官方路径](https://www.cgcookie.com/bundles/core-v2-5-2-lts-learning-path)

完整 Blender 入门路径包含大量本课非核心内容。即使它成熟，整套照搬仍会把本课改造成 Blender 基础课。大学 syllabus 能提供范围与评价参考；若没有资产、步骤、常见错误与教师用例，也不能解决备课生产问题。

比较的单位应是一段可运行的实践，不是目录标题。只考察：能否从材质起点进入、学生能否做一次非教程内的修改、教师需要补多少内容、授权及机房访问是否成立。建议给这次比较一个负责人认可的短时间盒，例如总计两个备课工作日；这是止损建议，不是工作量估计。若未找到明显减少原创补课和维护的胜者，停止寻找“完美主教材”。

重开有信息增益的条件，是候选确实减少资产加工、讲解重写、软件切换或排错工作。仅仅哲学表述更相近、版本更新或视频更多，不足以抵消更换成本。

## 5. Reference-first：保留借用策略，改掉“尽可能原样复刻”

建议改为：**先做课堂适配筛选，再复刻最危险的一段，最后最小改造。**

原样完整复刻在筛选之前，可能浪费数天跑建模、布景和复杂灯光；完成一遍也只能证明教师会做，不能证明学生能独立做。官方身份提供来源可信度，不保证教学适配度、授权范围、文件可用性或认知负荷。

筛选时只问几个具体问题：提供的是实际可编辑文件还是仅视频？是否有可用材质起点、所需贴图与坐标？从中途进入是否依赖前面建模/几何节点状态？能否分发给班级、学生是否能稳定访问？教师是否能解释并修复它？缺少这些条件时，普通但完整可教的成熟案例可优先于官方案例。

## 6. 双骨架：保留区分，取消双重编排

知识依据与实践载体当然不同。但没有必要为二者各维护一套完整顺序、编号和覆盖矩阵。

建议只维护一条学生实践顺序，每个关键步骤旁边放需要的理论说明和一两个来源。教师参考库保持查阅用途，不推动课程自动扩容。保留六行 LO 检查即可：本课程在哪一步让学生做出什么可见表现？缺证据时修任务，不是再加一个来源或一节课。

这接近“一条实践骨架，理论按需补注”。它也防止厂商课程决定评价：即使教程没要求独立修改和迁移，本课程仍必须要求；即使教程展示十种功能，本课程也不必保留。

## 7. Blender-first：可以是暂定起点，不能是逐实验必须先试的规则

“每个实验先试 Blender，不行再换”会重复支付探索成本。只需前置验证最高风险能力一次。核心比较应是总教学成本，不是软件图标数量：学生学习时间、模板黑箱程度、教师排错、许可与安装、导入导出损失。

以同一个要求比较 Blender 与 Painter：指定局部涂层区域需要改变，其他区域与指定通道须保持；学生需要保存结构、再次改动并解释方法。资产、修改复杂度和起点帮助应尽量相当，不能拿 Blender 空白图与 Painter 完整智能材质模板比较。

若 Blender 方案依赖一套教师自制的复杂多通道层系统或插件，学生只能调滑块，则“一个软件”很可能更贵。此时引入 Painter 有明确教学价值；不必因为偏好单软件而自己维护一个简化 Painter。

反过来，如果简单、可理解的遮罩与节点已满足本课修改要求，就没有必要仅为行业覆盖强制每人安装 Painter。学生至少应理解并实际使用某种非破坏性遮罩/组合方式；不等于必须操作某个品牌的 layer stack。

Blender Shader Graph 与 Designer 纹理生成图不能被宣告等同。若 LO4 是可理解的因果图和参数变体，小图足够；若要独立输出分辨率可控、可复用的平铺多通道贴图，则必须面对纹理生成与输出流程的额外成本。不得通过删除输出要求来宣称完全替代。

默认建议：Blender 作为观察与组装底座；Painter 是否进入学生必修取决于上述一次对比和许可条件。Designer、Sampler 都不默认安装。采集/生成结果可以作为事先保存的输入进入 Blender，让学生检查、修订或拒绝，而不是承担生成服务设置。

## 8. 连续实践与可展示成果的最小组织

以下是实践结构建议，不是 Week 1–8 排课或正式任务书：

- 主资产先达到一个简单但可解释的外观，学生预测和比较参数效果；理论随具体问题进入。
- 在同一资产上加入局部修改和小型程序化变化，要求解释修改依据、保留非目标部分，避免只照视频完成。
- 为其中一个表面提供生成、检索或转换来的候选素材，让学生作出选择并验证；保留失败输入和拒绝理由。
- 在一个教师提供的新载体或新修改要求上做短迁移，最后提交可编辑成果及明确交付件。

一张精修展示图可提高完成感，但不能吞掉材质学习时间。毕业式完整建模、布景、摄影、剪片都不应成为这个 8 周课程的隐性前置。展示成果应与简短的修改前后、解释和验证证据一起看。

任务结构有三种生产方式出现即可，不要求三者等课时、等难度或每人都搭建工具链。AI 素材应标明来源和生成条件；课堂现场生成可以演示，保存的真实输出是断网时的可靠输入。

## 9. 交付验证不能继续模糊

课程负责人需要作出的实质决定是：主要出口是可继续编辑的 Blender 材质，还是外部实时环境可使用的材质资产？现有文档同时承诺二者，成本却未拆开。

若是前者，课程可以要求在另一台机器/干净项目中打开完整包，并改变光照、视角与载体；这有实际价值，但应相应修订当前 LO6 的下游适配承诺。若保留当前 LO6，则至少保留一次受支持的实际转换和目标打开，不应只切换 EEVEE/Cycles。

外部目标应固定一个。只转换一个受限、已验证的材质片段即可，不必把全部程序图和整件复杂资产都烘焙出去。Blender 官方文档明确指出 glTF 材质系统与 Blender 不同；不能从内部节点可用推导外部交付可用。[官方 glTF 材质说明](https://docs.blender.org/manual/en/4.0/addons/import_export/scene_gltf2.html) 此链接用于说明结构区别，不作为 5.2 导出功能清单。

## 10. Golden Lab：保留最小教学包，暂缓框架

“老师只验证一次，之后每届复用”必须撤回。可靠目标是：首次投入后，后续只做低成本抽检和必要修复。软件、设备、访问权限和学生基础仍可能改变。

| `validate.py` / `render_reference.py` | 先用手动检查。确有重复负担才加一份可读脚本，不以文件数为目标。 |
| `make_variants.py` / `inject_faults.py` / 完整 `expected/` | 默认不建。初期手工保存两三个有教学价值的变体或故障文件更易维护。 |

“one script”也不应该变成最低配置。零脚本可教的包优于无人能修的一脚本包。二进制资产可以按现有仓库习惯链接或存储，不为此新建资产平台、manifest 或依赖管理体系。

## 11. Python 的 ROI 与验证边界

值得自动化的前提：操作已经手动稳定；每次输入输出定义明确；重复次数或故障损失足够高；有人能在课堂前排错；失效后有简单手动路径。

可用粗略账判断：`预计重复次数 × 每次净节省时间 + 预期故障损失减少 > 开发 + 调试 + 后续维护时间`。全部是实际估计，不应只填理想渲染速度。高风险首先意味着必须验证，不自动意味着应该自动化。

- 优先候选：检查丢失贴图/路径、批量低分辨率预览、按固定相机输出对照图、已稳定的批量导出。
- 暂缓：任意材质图通用验证器、全图像素差回归、随机故障注入框架、为每个实验生成全部笛卡尔参数组合。
- 粗糙度 × 灯光 × 相机的 30 张矩阵只有明确教学问题时才有价值。通常先用少数能区分假说的对照；过多图片会把自动化节省变成教师筛图负担。

后台渲染能力本身不保证跨版本、GPU、驱动、采样与降噪设置的逐像素确定性。脚本适合判断文件能否打开、资源能否解析、渲染能否完成等；外观是否符合意图仍需人审。结构检查也不能规定所有学生必须使用完全相同的节点拓扑。

故障练习应有可解释的证据与修复路径。一个节点断开不一定对应唯一外观，一个错误 UV 也可能引入多个混杂因素。先手工选出少数稳定、能教学的故障，再考虑批量化。

## 12. 版本策略与 MCP

本次官方索引支持用户给出的版本事实：5.2 LTS 于 2026-07-14 发布，支持至 2028-07；4.5 LTS 支持至 2027-07。[5.2 官方发布页](https://www.blender.org/download/releases/5-2/)；[官方 LTS 页面](https://www.blender.org/download/lts/)。这是网页证据，未实际安装验证。

建议目前优先验证 5.2 能否运行选定的 4.5 案例：打开、资源解析、关键局部修改、预览/渲染、必要导出和目标打开，以及视频/UI 差异对学生的影响。通过就用 5.2；出现实质教学成本且首届教学窗口仍在支持期内，可以冻结 4.5。开课前确定一套机房和教师共同使用的具体版本，学期中不追新，后续课前再复核。

版本应写在教学包说明里，六类学习成效不应绑定某个版本。记录补丁号有复现价值，但无需把每个补丁升级都做成课程架构门禁。

对附件里未展开的 MCP 设想，只作原则判断：Agent/MCP 可辅助教师探索或生成脚本，不应成为学生上课、打开文件和完成任务的运行依赖。Agent 操作成功一次不构成验收；有用的结果应落实为普通工程、说明或人工可检查的脚本。没有明确重复任务时，不建设 MCP 自动备课流水线。

## 13. 下一步与停止条件

停止继续设计：47 项逐项教学覆盖、独立双骨架、完整 Golden Lab 框架、自动故障平台、全工具演示套餐，以及尚未测量就宣布的时间节省。

继续利用：现有研究目录、Shah 现成实践与排错内容、PBR Guide 和 Dinur 的必要解释、官方资产与起点。保留六类能力词汇，改变它们的具体实现约束。

接下来需要的证据很小：

1. 核实真实课堂与作业时间、学生操作基础、机房/许可/网络条件，以及教师与助教支持容量。它们是选型输入；无需为等待回答停止这次独立审查。
2. 用现成资产试两个最危险环节：受控局部修改、受限目标交付。记录准备、恢复、操作、排错时间与教师补建内容。
3. 邀请少量与学生基础接近的试做者，完成不完全照教程的修改；教师自己的熟练复刻不足以估计学生时间。小样本只能发现风险，不能证明普遍学习效果。
4. 回到 Gate 3B，只保留经验证的主线及必要补丁。再进入正式 3C；不提前排八周、不新增全套实验包。

建议停止条件：如果必须重写大半教程、创建复杂编辑插件、从零处理资产管线或持续依赖 Agent 救场，放弃该案例/宿主组合，不以“再补一个脚本”延长投入。

**课程必须自己掌握的核心是：让学生作出判断、接受新修改要求、解释变化并验证迁移。模型、场景、菜单教程与重复机械工作，应尽量借用成熟方案。**
