## 2. Verdict：改什么，保留什么

现有方案正确地把结构判断放在视觉精修之前，也明确了课件完成不等于上线完成。真正需要改变的是：

1. **把两轮固定集体备课改为一次有实物的决策会，之后只复查失败点。** 已有结构基线不必先完整讨论一遍、再做粗 PPT 完整讨论一遍。存在无法理解的结构冲突时，才先开短结构会。
2. **原型以待验证问题为单位。** 需要验证讲述顺序才做页面序列；需要验证操作就用真实 Starter + Handout；需要验证辨识就用真实图像。不是每次都要一整套粗 PPT。
3. **把学生能否独立产出证据放到视觉生产之前。** 教师能顺畅讲完只是必要线索，不足以验证学习、软件操作与全班时间。
4. **传播是每次决定的完成条件，不是第五阶段的大扫除。** 原型中的课程决定先回到对应 authority，再更新消费者；只更新受影响部分。
5. **精修准入与课堂上线分开。** 原型过关允许投入制作，不自动关闭 Windows、分发、提交、真人排练门禁。

对五项假设的裁决：A「P 是 authority」成立，「P 全文应成为讨论界面」不成立；B 粗 PPT 有条件成立，不宜规定每次完整制作；C 应以决定及其验证循环为主；D 当前传播边界确实不完整，代码、指针与验证状态也在范围内；E 应用可观察准入条件替代「结构基本稳定」。

## 4. Hidden Blind Spots：比文件数量更隐蔽的问题

**任务状态没有自动复位。** H 步骤2让学生做纯黑、Factor=1的实验，步骤3却说节点「当前处于中性开局状态」。文件开局正确不代表执行到这里仍正确。应明确从当前测试状态继续设目标参数，或显式复位，二选一；这类缺陷最适合让未参与设计者按任务单实际操作发现。`LOCAL FINDING：H 任务B步骤2–3；修正为 PROJECT INFERENCE`。

**演练中的证据可能是脚本自己写的。** R 的「用时8分钟」是字符串，重开调用是同进程 `open_mainfile`；V 的决策卡由脚本写入再检查指定词句，图片用场景渲染生成。它们能检查部分资产与文件链路，不能证明真实退出新进程、学生预测、真实视口截图操作或上传路径。本次不否定 P §7.1 报告的历史 GUI 点检，只限定这些脚本本身能证明什么。`LOCAL FINDING：R L110–128；V L126–156`。

**一次「讲顺」可能是专家补全了材料缺口。** 教师知道颜色控件在哪、遇到错误能自行处理，初学者未必。原型测试应记录参与者实际卡住的位置和求助，不把教师临场解释全部算成材料已支持。无法找到学生时可用陌生同事检查指令，但必须注明不是学生学习验证。`PROJECT INFERENCE；依据外部研究见§5`。

**屏幕注意力也是资源。** 学生同时看 PPT、Blender、纸质或电子任务单时，窗口切换和寻找位置会吃掉操作时间。练习阶段投屏只保留目标、停止条件、求助入口；详细步骤留在任务单，教师演示时明确「先看，再做」。这是应试测的组织方案，不是新增强制课堂纪律。`PROJECT INFERENCE / RUNTIME REQUIRED`。

**进度与存储身份可能混淆。** P §5要求 `.blend` 本地留存供后续核查，§8又指出机房还原卡未知。当天能重开不证明下周文件仍在。应沿现有交付门禁确认持久目录或校内备份去向，不能靠「本地留存」四字闭环。`LOCAL FINDING + RUNTIME REQUIRED`。

**导学可能意外冻结后续周历。** E 开头明确 W2–W6 周次未冻结，P Block1及H导学却使用确定语气列出逐周路径。可呈现能力发展方向，但应保留候选身份；不应由PPT制作自行把候选周次变为承诺。`LOCAL FINDING；实际权威仍需核对远端`。

**第一次数码调节发生在计划第85分钟。** P 前四Block合计70分钟，演示再15分钟；这不等于前85分钟无活动，Block3有观察填写。应检验这段铺垫是否真正改善后续判断，而不是因为软件课就武断把操作全部提前。用现有Block试走比较即可，无需先重排全课。`LOCAL FINDING + PROJECT INFERENCE`。

**成功修订不等于人人都该把0.85改成0.80。** 三字段可记录对照反馈后的有理由调整，不能把指定颜色/数值当普遍达标答案。对已经合适的作品，如何证明判断与修订应由课程负责人明确；不要由Agent擅自取消既有「修订动作」目标。`PROJECT INFERENCE；P §1.2、Block8，H步骤4`。

| 架构 | P结构审查→结构会→粗PPT→试讲会→同步→精修→上线验收 | 从现有P提取讨论视图，携真实任务片段开一次会；争议决定→测试→传播→局部再验 | H任务顺序+Starter构成主要体验；P保留时间/恢复，少量投屏只用于观察和共性讲评 |
| 教师负担 | 中高；固定两轮完整审查容易重复 | 较低；只看待决问题与学生/操作证据，但须参加关键试走 | 上课导航可能简单，备课初期须重构讲授与任务提示 |
| Agent负担 | 中高；全量派生与多阶段同步 | 中；影响定位与局部修订，需要语义判断，不能只替换词 | 初期高；任务顺序/屏幕支持重设计，此后可能下降 |
| 长期文件数 | E、P、H、PPT共4类；粗PPT若另存会变5类 | 同4类；讨论视图和验证副本无独立维护生命周期 | 可仍为4类，但PPT较薄；不是通过改名减少SSOT |
| 同步成本 | 中高；完整Prototype/Final分叉风险 | 较低；共享字段回源，页级表达局部改 | 中；H与软件界面的依赖更强，任务变更会连动两者 |
| 返工成本 | 结构晚发现时仍高 | 集中在已暴露的高风险片段；前期漏测仍会返工 | 初期改造较大，后期视觉返工少、任务返工贵 |
| 问题最早发现 | 第一会发现文本问题；第二会发现讲述问题 | 准备会前/会中即发现指令、视觉、恢复与学习证据问题 | 学生任务试做时很早；长讲述节奏未必得到检验 |
| Classroom reliability | 补足真实探针后可高；七阶段本身不保证 | 更贴近当前薄弱处；仍取决于目标机房与现场门禁 | 操作路径集中，但屏幕管理和大班反馈依然需验证 |
| W2–W9扩展 | 每周重复七阶段成本可能上升 | 可复用判断原则，不能复用W1页面数、时间或门禁结论 | 对实作/工作室周可能适合，概念密集周须重新判断 |
| Drift风险 | 中高 | 较低，前提是Notes不独立更改课程规则 | 中；若H升级为实际课程authority而P未同步会恶化 |

A适合存在重大结构分歧、需要多位教师明确先行达成共识的情况。C是真正不同的备选，但当前没有证据证明值得为W1改造全部交付方式。B使用已有投入，最符合此次最小改动目标。

另一常见架构是新增YAML/JSON课程模型，同时生成P/H/PPT。当前不推荐：它会新增编译器、schema、例外处理与编辑入口迁移，未证明净节省。可以先用已有Markdown标题和任务编号，不为「Agent方便」另建课程数据库。

## 7. Recommended Workflow：五阶段，内部按决定循环

**决定 → 用最低成本验证 → 回源并传播 → 只复验受影响链路。** 这是各阶段共同动作，不是新增四次会议。

| 阶段 | 教师投入 | Agent工作与完成标志 |
| --- | --- | --- |
| 1. 准备有问题的讨论视图 | 看保护核心与真正待决问题 | 从P §1/3/4/6提取只读视图，附H任务指针、当前基线与待决项；准备已知高风险真实片段。无争议内容不重新审定 |
| 2. 一次集体决策与低成本试走 | 围绕「学生要做什么、怎样知道会了、卡住怎么办」判断 | 概览完整11Block；实际走关键片段，使用真实H/Starter/观察图，必要时翻粗页；记录失败和决定，不讨论无关装饰 |
| 3. 局部修订、传播、复验 | 只处理新增的实质性取舍 | 同一修改批次内更新authority与消费者、纠正指针、失效旧验证。失败点再测，满足§10才投入精修；不固定再开全体大会 |
| 4. 完成单一课堂课件 | 检查关键图、话术与教学节奏 | 在同一受控课件链路中补清晰截图、必要标注、页级Notes；检查任务显示/答案揭示时机与呈现环境 |
| 5. 真实交付验收与首次课堂反馈 | 按现有要求完成真人连续走课；首课观察实际学生表现 | 关闭有证据的目标机房/分发/提交门禁；首课只记录阻塞、关键错因、证据缺口并回写相应位置 |

Windows打开Starter、投屏清晰度、分发提交等高风险探针在阶段1–3可提前做，不必等待第五阶段。第五阶段确认最终组合，不把每项探索拖到最后。

临时teacher view建议只呈现「Block/分钟｜学生动作与产出｜教师判断点｜超时或恢复入口」，展开才见细节，页首显示P版本。它可以出现在聊天、临时渲染页面或现有文档的临时选区；默认不提交仓库、不手改，源变更即失效。教师在视图上提出意见，Agent回写P，再重新生成。**不可重建的独有内容一旦留在视图里，它就已经成为第五份主稿。**

## 8. Artifact Responsibility Matrix：不强求内容完全正交

正交的应是**修改权与责任**，不是字面内容。学生在活动页看到与H相同的提交要求是合理重复；让教师上课跨三份文件查一个关键提醒反而增加负担。

| Artifact | Authority范围 | 自动生成与派生边界 | 不应独立维护的内容 |
| --- | --- | --- | --- |
| Project Authority（既有教师决定/Issue） | 要不要教、要求多深、课程/考核取舍、采纳状态 | Agent可整理待决项与已采纳决定；不能把建议自动升为采纳 | 不另建平行决定总台账；聊天中的明确新决定只需在既有落点固化 |
| E | 外部依据定位、覆盖缺口、决策路由及边界 | 检索/指针检查可自动；新证据判断需核验 | 不记录页面顺序、会议流水账、每次字体调整 |
| P | 周教学契约：成效、核心/可裁、活动顺序与时间、证据标准、恢复、教师答案与语义边界 | 可自动摘取讨论视图和执行提示；课程修改由已采纳决定驱动 | 不维护每页讲稿、截图坐标、动画顺序 |
| H | 学生实际看到的题目、字段、步骤与交付界面；任务语义服从P | 可生成初稿，需按真实任务审读；措辞/版式可局部维护 | 不另订成效标准、恢复达标规则或全课周次；也不是把P全文复制给学生 |
| PPT可见层 | 具体页面表达、图像、揭示顺序、活动停留提示 | 从P/H生成骨架；真实资产与关键图需核验；允许人工设计 | 不偷偷加任务、减保护核心或修改达标条件 |
| 内嵌Presenter Notes | 本页如何讲、何时停/切Blender、指向哪个任务、下一步动作 | 自动摘取关键约束+人工页级提示；带P Block/H任务指针 | 不重新撰写另一套时间/恢复/术语政策，不另存独立Notes主文档 |
| Teacher view / 原型副本 | 无课程权威 | 可随时重建、覆盖；携源版本与问题范围 | 不存唯一决定，不承接长期评论积压 |
| Starter/Recovery/构建脚本/验证代码 | 实际软件行为与资产实现；受P教学契约约束 | 现有构建链路可重建；运行证据需指定环境 | 不把课堂术语、固定示例答案当跨版本不变量；重建不是已验证 |

建议Notes最小结构是「本页意图一句｜关键口述提示｜动作/转场｜必要边界提醒｜源指针」。不规定每页字数或强制五栏；某页需要离线可直接读的错误恢复提醒，可以从P摘入。其准则是教师能独立使用，而不是为了消灭重复牺牲可执行性。

**PPT也不是完全可由P重建的纯派生物。** 构图、标注和讲述节奏有独立设计价值，应由唯一课件编辑源保存。若选PPTX为编辑源，就维护这一份；若选代码生成课件，就维护生成源，PPTX只是输出。不要人工改生成结果后又全量覆盖。当前不要求为了生成化迁移工具链。

## 9. Change Propagation Rules：最轻的影响模型

沿用 `KU-W01-*`、P的Block/小节、H任务A/B/C；页Notes引用这些锚点。Block顺序改变时一起检查引用，不把页码当语义身份。无需新注册表、图数据库或每句文本的ID。

Agent对每次修改仅形成一条短记录，放在当前审阅线程或既有Issue/提交说明：**决定及权限状态｜改变的语义/字段｜影响落点｜不改项及理由｜需要复验的证据**。人类看取舍，Agent承担跨文件判断。不能保证语义依赖完全自动发现，但能把人工逐文件核对变成一次结果审阅。

| 修改类型 | 首先落点 | 条件传播 | 最低复验 |
| --- | --- | --- | --- |
| Teaching decision：删讲点、改深度/LO/任务/成效 | P；需要时先落实教师采纳记录 | H相关题/字段；PPT与Notes相关页；E仅在知识单元边界/决策路由变化时；代码/资产仅在实现或断言依赖时 | 对应任务还能产出所需证据；时间/恢复是否受损 |
| 时间、顺序、Cut/Recovery | P对应Block或规则 | Notes节奏、H步骤/恢复、PPT揭示/转场；E引用锚点若变即修 | 受影响Block及前后交接；重大顺序变更重走完整流程 |
| Implementation：控件名称、参数、文件路径、资产版本 | 资产/脚本及P接口说明 | H操作步骤、相关截图/PPT/Notes；E仅涉及官方版本/来源变化时 | 真实操作、恢复及保存链路；重验受变更影响的host结论 |
| Presentation：字体、裁图、排版、等义话术 | 唯一课件编辑源 | 一般不动P/H/E；若裁图去掉判断线索或改变题意，升级为教学修改 | 投屏可读、语义/揭示顺序保持 |
| Evidence/research：来源错误、概念依据变化 | 一手依据定位与E对应条目 | 只改消费该错误主张的P/H/PPT/Notes及相关断言 | 主张—pointer一致；教学修正需要的局部试走 |
| 验证证据变化：某路径失败、只在macOS成功 | P现有门禁/对应证据位置 | Notes/H运行路径或降级提示；相关受影响截图/资产 | 修正后的实际路径；其他独立证据不一并作废 |

执行次序：定位authority → 搜索直接词句及语义邻项 → 列最小影响集 → 对已授权决定成组修改 → 重新扫描旧说法与指针 → 重验受影响链路。未决教学取舍保持提案；已有明确教师决定无需再反复请求同一授权。

**工作示例：教师决定「W1不讲 Transmission vs Alpha」。** 以下解释为取消学生端讲授/要求，不改变「两者不同」的知识事实，也不删除镜片资产。

| 载体 | 本例处理 |
| --- | --- |
| P | 改Block2/4的主动讲授要求、§5.3学生范围；§1.3可保留教师背景纠错，但明确不是W1学生考核内容；检查LO/答案口径一致 |
| H | 删除任务A下的强制术语纪律；镜片观察是否仍作可选自然语言描述按教师决定落实，不自动删整行 |
| E | 查看KU-W01-1/2范围是否需明确不教该辨析；若未承载该要求或错误路由，可不改。不把科学来源删掉，也不自动把讲点排到W6 |
| PPT与Notes | 学生页移除相关解释/问题；Notes仅在必要时保留简短教师背景提示，不能继续主动讲授 |
| Starter/Recovery | 原则上不重建：取消讲授不改变玻璃材质或受保护区；必须检查是否有含该要求的内嵌说明 |
| V/R脚本 | 实际命中V L130/L147的模拟卡与硬编码断言、R Block2–4文案；需移除过时教学要求，保留贴图打包/保护槽/持久化等工程检查 |
| 验证状态 | 相关内容一致性与讲述片段待重验；没有资产变更时不无差别推翻全部历史资产验证；既有Windows未验证状态仍未关闭 |

这里最重要的机制是：**区分「删除教学义务」「删除事实」「删除实现」**。只用全仓搜索替换会混淆三者。

## 10. Prototype Gate：允许生产，不代表允许上线

以下为 `PROJECT INFERENCE / PROPOSED` 的四项准入判断；在现有审阅记录里各写一句通过依据或未通过原因即可，不新建门禁文档。

1. **契约可说清。** 教师确认本次保护核心、学生任务与最低证据；影响页面/任务结构的争议已解决。细节措辞、美术尚有待办不阻断。
2. **关键任务确实走得通。** 用当前H、Starter与真实关键画面完成一次预测/操作/反馈/修订/保存/交付的代表性片段，并走一次最相关恢复分支；没有依赖教师临时发明步骤的阻塞。受试者身份如实记录；专家通关不记为初学者通过。
3. **完整流程可交接，预算有归属。** 教师从开场到收尾说清每次「看/听/做/填/交」切换；关键耗时有试走依据，其余仍标PLAN BUDGET；采集、点评、上传、恢复没有未分配的隐藏时间或重复花掉的缓冲。短试走不冒充160分钟实测。
4. **材料属于同一修订，且无已知架构阻塞。** P/H/关键页/资产版本匹配，决定已传播，没有会推翻题型、操作路径或核心视觉的未决问题。晚做的只是生产与最终环境确认，不是尚未弄清能不能教。

若只有目标机房访问暂不可得，但不会影响相关页结构，可先制作稳定的概念/活动页；版本敏感截图与依赖该路径的页保持暂定。若机房问题可能迫使重做操作方案，则只暂停这部分精修，不把「未知」当通过。

**课堂上线仍受P §8/10四类既有门禁约束：真人连续走课、分发、提交、目标Windows运行时。** 原型小样既不能关闭全班学习耗时未知，也不能取代现有160分钟真人排练要求。任何变更只使相关验证失效；不是字体变化也重跑整套资产测试。

### 原型的允许项、禁项与生命周期

| 问题 | 建议 |
| --- | --- |
| 允许什么 | 真正的学生指令/问题、关键真实截图或直接打开资产、简陋标注、必要对照、最少口述与转场提示；页可以只是一张图或一个任务 |
| 禁止什么 | 无关精修、全套动画、为了凑2–4点添加正文、先写完整逐字讲稿、无判断目的的高成本搜图；不禁止用于检验遮挡/揭示的简单动画 |
| 多久有效 | 只服务当前待验证问题与当前源版本；决定已回源或源发生相关变化即失效。不得因「还可能用到」维持第二套长期版本 |
| 自动生成吗 | 骨架和引用可生成；精确视觉/任务语义需检查。Agent生成不等于确定性编译，不保证无漂移 |
| 覆盖旧版吗 | 默认只保留一个活动原型；意见先归入authority后覆盖。需要解释某个决定时留一张前后对照即可，不建立原型档案工程 |
| 进入repo吗 | 默认不提交每轮临时PPT二进制；可用现有本地临时区。需要复现实验时保留最小轻量源或既有审阅记录中的片段，不提交受限商业素材 |
| 可丢弃吗 | 原型作为验证载体可丢弃；决定与有用观察应保存到原有落点。若同一课件直接演进为正式稿，也可以，但只有这一条活动编辑链，不能并行维护prototype/final两套 |

## 11. Stop Rules：到哪里已经够了

- **停止研究**：当来源足够确定事实边界、剩余分歧只能靠学生/目标软件运行解决时，停止加文献。当前无需再搜更多「原型优于精修」文章；把时间用在关键任务试走。发现新的承重来源矛盾才重开定向研究。
- **停止补文档**：若待加内容不改变任何教师决定、学生动作、验收标准、恢复路径或来源定位，就不加。一次会议意见在P的局部修改中已体现，不再复制成长期Spine、会议纪要总表与新规范。
- **停止原型迭代**：四项生产准入成立，余下问题只涉及可读性和制作细节，即可进入生产。不能要求无人再提任何建议，也不以固定轮数制造通过感。
- **停止精修**：图像能支持判断、投屏可辨、教师能顺畅切换、任务/来源无缺口，就完成。装饰增加但不改善上述能力，不继续投入。
- **停止全量同步/测试**：与本次语义无依赖的材料保持原样；影响集内复验已通过，无新失败，不重复跑全套。保存一个配套版本身份即可，不增发布数据库。
- **重开条件**：新证据否定事实、真实学生无法形成核心证据、目标环境失败，或教师改变任务/成效；不因新的版式偏好重开教学结构。
- **不要无审查推广**：W1首课后，在既有记录中简记教师审阅耗时、返工原因、学生阻塞与漏同步情况，用来判断B是否值得复用；没有实测前不宣称节省工时。W2节点搭建、W5图像保存、W7–W9项目制须按各自风险另选验证片段。

## 12. Specific Recommendation for Week 1：下一步就做这一件事
