## 2. 独立裁决：问题选对了，优化对象选偏了

课程使命仍值得继续：以参考和视觉意图为依据，制作、解释、受控修改和重新验证材质。这比软件菜单或单一生产流程更稳定。

当前风险在于把“内容条目能覆盖 LO”当成“学习经历能形成能力”。软件功能文档能够证明一个操作存在，不能证明初学者经过该操作就能独立判断，更不能证明学习成本最低。

无需追求数学意义上的全局最小，也不能把证明失败直接解释成 14 项一定过多。真正的决策对象应是：

> **在明确的学生起点、资源与时间内，足以反复产生目标表现，并允许失败恢复的课程组合。**

要计算的不只是软件数和内容数，还包括练习次数、反馈、等待、资产准备、格式转换、模板维护和出错后的恢复成本。一个软件内搭建复杂替代系统，也可能比两个成熟界面更昂贵。

## 3. 五项最有杠杆的纠偏

### 3.1 先确定“能做”的证据，再确定内容和软件

Gate 3B §4 的删除测试证明了若干收益值得关注，没有证明这些收益必须分开教、由同一种操作产生、或由特定软件承担。§11 的“严谨闭环 / NONE”超出了现有证据。

建议用一份小型验收样例约束选型：学生面对参考，提出外观目标；改变一个关键材质关系；接到局部修改要求；在新观察条件下验证；能说明变化与保留项。六类 LO 可以在这个闭环里反复出现，不需要六个模块或十四个独立练习。

“必须学生自己做”应指学生对预测、选择、介入和结论负责，不必指其完成所有鼠标步骤。反过来，别人操作也不能成为学生只看演示的理由。

### 3.2 路径依赖早于 Gate 3B，有限重开 3A 的实现描述

Gate 3A 的六类名称宽泛且可保留，但 §3、§4 的细化已经收窄：

- LO1、LO3 把物品历史、底材—涂层—磨损—污垢写成主要表现；
- LO4 偏向无缝表面、消除平铺、封装接口；
- LO5 与 LO3 被解释成“素材前处理—资产装配”的分工。

由这些描述再推出 Painter + 程序化宿主 + Image-to-Material，自然会产生貌似唯一的结果。应重开这些具体化描述，保留六类共同语言与来源研究。

新的信息增益是：允许比较干净表面的工艺与光泽设计、局部印刷/涂饰、共享遮罩依赖、AI 辅助局部修改等实现；返工限于教学映射，不需要重审教材。

程序化不必等同于独立程序化材质作品：例如同一遮罩如何同时控制区域颜色与粗糙度，改变边界为何带动两个通道，就是可与 LO3 合并的因果练习。是否足够达到 LO4，仍须看学生能否解释、改动依赖并迁移，而不是只会拉现成滑块。

### 3.3 作品好看、过程流畅，都不足以证明学会

一个持续道具会把软件熟悉度、模板记忆与知识迁移混在一起。AI 进一步放大了“交付成功”与“独立能力”的差别。

建议最终证据包含两部分：

- **可展示成果**：材质外观达到明确意图；必要资源可打开；保留足以完成约定修改的源文件；注明外部输入和本人介入。
- **个人能力抽查**：在未练过的小样、部件或故障上，先提出预测或诊断，再进行有限修改并检验。不必禁用软件帮助，但在这段短检验中不让 AI 代替诊断和决策。

评分不应只奖励做旧细节、漂亮构图或生成次数。可同时检查意图是否实现、因果解释是否与操作一致、修改是否越界、验证是否发现问题。不在当前阶段编造权重与统一分钟阈值。

还要防止走向纯维修课：每位学生至少应从简单起点决定并构造一个核心材质关系，而不是全程在教师完整作品上查错。“从简单起点构造”无需等同于空白工程、从零建模或逐像素手绘。

### 3.4 初学者的判断力需要受控对照，不能靠责任声明产生

“学生负责最终验证”是责任边界，不是教学方法。初学者需要看到同一条件下可比较的好坏样例，并练习一次改变一个因素、提出预测、观察结果和修正解释。

可将三类短经历嵌入持续创作：

1. **外观因果**：在固定观察条件下改变 Roughness、Normal 或灯光之一；回答变化来自哪里。
2. **局部控制**：只改变指定区域或关系，指出哪些通道应联动、哪些应保持。
3. **支撑故障定位**：在预制正确/错误资产之间，用 UV checker、替换已知正确材质、关闭法线贴图等方法，定位到贴图、坐标/几何、烘焙或目标配置层。无需独立修完整高低模管线。

这些是建议的表现类型，不是新的“必须恰好三个实验”。正常练习可以合并它们，早期不要同时埋入大量故障。

一个额外盲区是把反演当作答案读取：单张参考通常不足以唯一确定真实通道。原始材质估计研究明确依赖形状、光照和反射模型假设；它不能提供一个普适的“照片即真值”保证。[Karsch & Forsyth 原始论文](https://arxiv.org/abs/1912.11568)

因此 LO1/LO5 也应允许学生说“证据不够，需换灯观察、增加参考或选择较保守表示”。拒绝、替换不合适的来源也是成功决策，不强制把每个坏结果都修好。

### 3.5 容量瓶颈可能是反馈，而非软件

56–72 小时只是情境总量，没有包含经过试跑验证的操作、失败、反馈与返工分解。Gate 3B 的节省 8–10、6–8、4–6 课时同样没有试跑依据，且“课时/实际小时”需统一。

若每次都要教师逐人打开工程，持续项目可能在反馈环节失效。粗略预算应分别计算学生总负担与教师反馈总负担；课外时间不能自动替代课堂中有指导的失败诊断。

保留少量统一检查视图、固定格式的前后对照、清楚的修改边界，有利于快速反馈。是否使用同伴互评取决于其判断是否经过校准；不能假定把互评交给学生或 AI 就消除了教师负担。

## 4. 实践结构：保留连续性，松开“同一个资产”

### 首选待试路径：持续视觉 brief + 材质版本系列

持续的是视觉目标、材料语言与可编辑版本；物体是承载这些决定的试件。

例如，在预制的简单物体上实现一个明确的表面意图，接到“保留总体色彩，改变局部触感与光泽”的新要求，再把该材料关系迁移到另一种形状或使用尺度。题材可选，但模型数量和结构由教师控制。至少有一个干净、非做旧的要求，以检验课程是否摆脱“材质 = 锈蚀脏污”。

每一轮循环：**观察/提出意图 → 制作或选择候选 → 对照 → 受控修改 → 在新条件下验证 → 保留版本。** AI 可以进入其中的多个步骤。

相较“一件道具做八周”，优势假说是：仍能积累可展示作品，但可更早检验同一材质在不同形状、尺度与环境中的表现，也不必让一个道具硬装下全部能力。

风险是素材与文件管理增长、学生觉得项目碎。控制办法是共享一个 brief、一个主要工程和有限的预制小样，而非不断新增完整项目。

### 真正值得比较的替代路径：材质诊所 + 小型自由创作收束

主要实践从半成品、错误案例和客户修改单开始，逐步减少提示，最后独立完成一个范围很小的作品。连续性来自同一套判断方法和个人版本档案，而非同一对象。

这适合探索学生基础差异大或可指导时间较少的情境：每次挑战可以直接聚焦一个表现，失败不拖垮后续项目。但这是待验证的适配关系；它也增加教师案例准备成本，并可能削弱创作投入。

若采用此路径，必须保留学生自己决定外观与构造关系的机会，不能变成有唯一答案的故障题库。

**暂不推荐第三条完整 AI Agent 驱动课程路径。** 它可以作为上述任一路径的生产辅助方式；若新增代理部署、脚本调试与运行环境维护，其信息增益未证明值得占用本课容量。

## 5. “景—球—物—景”应是观察切换，不是课程阶段

开头用一个完成场景建立兴趣合理，但不必导入完整游戏/影视工程。末尾回到使用语境也合理，但不应把验证推迟到最后。

建议保留比喻，取消线性约束：

- 场景/参考回答“为什么要做成这样”；
- 测试小样帮助隔离某个变量；
- 物体检验空间分布与局部修改；
- 验证场景在每轮迭代中出现。

材质球不是普适中立观察器。为教学选择有曲面、平面、边缘或接缝的简单试件，取决于当前要观察的现象；不必为此建设复杂标准器系统。

“保持材质成立”也不等于换灯后外观不变。对照应确认其响应仍符合意图与合理预期；做跨环境归因时先控制灯光、相机、曝光、尺度等变量，再逐个引入差异。任意两个场景看起来不同，不能自动归因于渲染器。

## 6. AI：早进入，逐步交还验收责任

不必先学完所有基础才能看到 AI，也不应从第一天就要求独立审查任意生成结果。

| 学习情境 | AI 可以承担 | 学生须留下的证据 |
| --- | --- | --- |
| 初次接触 | 提供预生成候选、示范一次受限生成；教师提供可靠对照 | 先说明观察目标，再指出接受/拒绝的可见理由；结论可由教师校准 |
| 因果练习 | 提供候选通道或建议，按固定条件生成 | 学生先预测、进行受控干预、对照结果，AI 解释不直接当答案 |
| 构造与修订 | 生成局部图样、遮罩、变体或短小节点结构 | 学生界定修改范围，能追踪关键依赖、撤回错误改动，并复核无关部分 |
| 综合创作 | 自主选择生成、检索、程序化或手工路径 | 能解释方法选择、保留必要编辑能力、在新条件下验证 |

AI 贯穿是责任与比较方式贯穿，不要求每次开一个在线工具。提前缓存真实 AI 输出可以保证练习连续；它不证明学生会调用生成工具。如果课程还要求独立生成，则必须单独验证该环节的可达性与成本。

同样，传统生成器、自动烘焙和宏脚本不能仅因自动化就统称为生成式 AI。要在实际例子中说明输入、输出及可靠性边界。

## 7. 软件裁决：先决定输出契约，再做局部比较

### Painter

官方文档支持它的图层、多通道与局部遮罩能力；这足以支持“强候选”，不支持“唯一宿主”。[Painter Layer stack](https://experienceleague.adobe.com/en/docs/substance-3d-painter/using/interface/layer-stack/layer-stack)

不值得为反对路径依赖而重做一次全软件市场调研。若 Adobe 可用、教师熟悉，而且空间局部修改是经试跑确认的高频需求，Painter 可以继续成为主力。只有许可、课外访问或实际任务成本显示问题时，才做针对性替代比较。

Blender 官方也提供直接在 3D 模型上绘制纹理的能力，但这不证明它具备同等便利的多通道非破坏性工作流。单软件候选需通过共享遮罩、关键通道联动、保存/重开/导出测试，不能拿“也能画”代替比较。[Blender Object Modes](https://docs.blender.org/manual/id/4.5/editors/3dview/modes.html)

### Blender 与 Designer

应比较同一个小任务的最小实现，而不是 Blender 小图与 Designer 全体系。Adobe 官方明确：参数暴露不要求初学者掌握函数图数学，因而复杂函数系统不是公平比较中的默认负担。[Designer 参数暴露](https://experienceleague.adobe.com/en/docs/substance-3d-designer/using/substance-graphs/manage-parameters/exposing-a-parameter)

必须先回答：期末需要宿主内可编辑 shader，还是可带入另一目标的 PBR 图像与资源包？Designer 的图输出、参数与发布机制面向可复用贴图生成；Blender 的 shader 图不能被直接视为通用可交换材质。其 glTF 导出器只转换识别到的节点配置，法线复杂配置可能需要烘焙成贴图。[Designer 图核心概念](https://experienceleague.adobe.com/en/docs/substance-3d-designer/using/substance-graphs/substance-compositing-graph-key-concepts)、[Blender 4.5 glTF 导出](https://docs.blender.org/manual/en/4.5/addons/import_export/scene_gltf2.html)

这意味着若最后要求网页 3D 发布，Blender 的“零切换成本”可能转化为烘焙、导出、目标重建成本；若只要求宿主内验证，它可能更省。两者都需要实际比较。

公平试跑需控制：同一外观目标、同等模板支持、同一局部变体、同一输出要求；比较完成时间、教师提示、失败恢复与学生能否解释依赖。若同一批学生连续试两种宿主，要避免把第二次任务熟悉度当成软件优势。

### Sampler、目标与标准

- Sampler 应作为可选来源/转换入口，不能因为 LO5 存在就自动成为第三个必修软件。官方证明 Image-to-Material 能从单图生成 PBR 材质，不证明每张输出均可用或本课必须使用它。[Adobe Image to Material](https://experienceleague.adobe.com/en/docs/substance-3d-sampler/using/filters/tools/image-to-material)
- EEVEE 与 UE5 不能以一个“或”消除二者在安装、导入和运维上的差别。先选一个稳定的教学观察环境，再定义一次有明确目标契约的适配经历。
- Cycles 对比可缩成教师预置、学生解释的比较；不要把打开第二引擎本身计作迁移能力。若目标包含亲自适配下游，则仍须保留一次资源映射/加载/验证经历，不能用两张截图替代。
- 保留参数语义、表示与交付的区别；标准名称无需独立占据必考单元。需要时嵌入解释即可。节点图思维不自动等于 MaterialX 互操作能力；不写 XML 是合理减负，但不足以证明六个 LO 已达成。

## 8. Sketchfab：有用的可替换窗口，不作为承重基础设施

核实到官方资料仍介绍 Model Inspector 的通道拆解、Download API 的认证下载、Data API v3 的上传发布。[Inspector 官方介绍](https://sketchfab.com/blogs/community/inspect-models-and-textures-like-never-before/)、[当前功能页](https://sketchfab.com/features)、[下载流程](https://sketchfab.com/developers/download-api/downloading-models)、[Data API v3](https://sketchfab.com/developers/data-api/v3)

这些资料证明功能文档存在，不证明中国课堂的网络可用率、具体账户额度、资产许可或学生上传成功率。本次未登录下载或上传，也未逐资产审许可。

建议优先级：

1. 精选案例观察和对照，可使用，但不能把上传作品当作正确 PBR 的权威答案；
2. 教师筛选后的素材来源，条件是对应许可与文件结构适合课程；
3. 可选展示，不能成为及格条件或课程连续性的唯一出口。

更基础的教学推论：Inspector 观察到的是发布结果，不能据此还原作者原来的图层、节点依赖或制作决策。因此适合外观/通道分析，不足以独立承担 authoring 教学。

课程首先应在可用的本地材料包上成立；包内资产的再分发需逐项确认。最终展示可用标准渲染、转台与修改对照；如果 3D 在线发布有独立教学价值，再做实际网络、账号、许可和完整上传验证。

## 9. First Cuts：裁实现负担，保留学生表现

不全盘否定原裁减顺序。减少去光照工具操作、参数封装、第二渲染器配置可能合理；把相关学生判断一并改成被动听讲才是问题。

| 优先压缩的实现 | 应保留的表现 |
| --- | --- |
| 从零建模、复杂 UV、完整高低模烘焙；预置正确资产与可恢复版本 | 遇到错误能定位到材质之外的支撑层，知道何时停止改贴图 |
| 完整做旧链、强制锚点联动、复杂手绘细节 | 构造核心关系并执行一次真正受控的局部修改 |
| 独立 Sampler 配置、每人现场生成、强行救回坏输入 | 对实际 AI/外部候选作出接受、拒绝、替换或有限精修决定 |
| 自己封装参数面板、平铺打散系统 | 理解一个依赖并实现/解释有意义的变体，不能只拖黑盒滑块 |
| 独立引擎搭建、复杂双引擎匹配、网站发布 | 换灯/视角复核；按既定最低目标完成一次适配与检查 |
| 单独标准巡礼、复杂工程术语展示 | 理解正在使用的通道、表示与目标约束 |

若仍放不下，应缩减材质复杂度、作品体量与表现深度，并公开剩余能力边界，不能同时保留“全部独立达成”的宣称。

## 10. 到 Week 1–8 的最短决策路径

### 10.1 冻结与重开

**可保持稳定**：8 周、Material/Texture Authoring 主科、三种范式、实践导向、双应用背景、47 项研究目录、已选来源角色、六类 LO 共同语言、操作自动化不等于知识失效。

**有限重开**：LO3/LO4/LO5 的具体实现映射；必修表面复杂度；独立完成与模板支持的界线；持续资产 vs 持续 brief；交付格式；软件宿主；First Cuts；固定的 14/10 数字与容量判断。

**不值得现在重开**：教材选型、完整 provenance、工业标准大全、所有替代软件横评。现有不确定性主要需要教学现场证据。

### 10.2 最轻证据关闭方式

| 问题 | 最轻方法 | 会改变什么 |
| --- | --- | --- |
| 真正可用的课堂/课外时间、班额、许可和课外访问 | 负责人/教务/机房事实确认，形成简短约束记录 | 软件可选集合、支撑范围、反馈节奏 |
| 学生基线及初学者能否诊断、修改 | 代表性学生试跑，包含较弱基础者；不能只看教师或优秀学生 | scaffold、必要练习与独立深度 |
| 模板、导出、重开与展示是否可靠 | 教师在实际机房配置 dry run | 首轮学生试跑是否有运行前提 |
| 单一资产是否产生迁移假象 | 换一个陌生形状/尺度/材质目标的小任务 | 是否需要第二载体；不增加完整项目 |
| Blender/Designer/Painter 是否真有必要 | 仅对试跑暴露的争议做等价任务比较 | 宿主和自动化边界 |
| AI 助手是否掩盖理解 | 有支持练习后进行短的独立预测/介入检查 | AI 权限与提示何时撤减 |
| Sketchfab 是否可作必需环节 | 只有拟让它承重时才实测网络/账号/许可/完整发布 | 采用或保持可选 |

### 10.3 顺序

1. 用少量事实确定可用时间、学生起点和资源硬限制；同时给出一份最低学生成果/能力证据样例。
2. 教师用已可用的工具准备一个可恢复的小型完整闭环，完成 dry run。
3. 让少量代表性学生试跑，记录预测、修改、迁移、教师介入和恢复成本；不设新的“20 分钟必达”等伪精确标准。
4. 只对试跑暴露的瓶颈比较第二种实现，确定条件化基础组合及裁减方案。
5. 将结果简短写回教学决策并完成必要的 Candidate 教学处理回填，然后开始 Week 1–8。

这相当于让 3B 与一个有限 3C 试验迭代，而非等 3B“最终裁决”后才接触任务。现有 Issue 仍保持原状态；本审查建议调整顺序，不声称已解锁或执行后续 Gate。

允许开始周程设计的实际条件是：有真实容量与资源约束、试跑过至少一个闭环、明确最低独立表现和支持边界、可运行的宿主与输出路径、可承担的反馈和失败恢复安排。无需等到全局最优，也无需把所有 optional 平台问题关闭。小样试跑仍不证明全班八周必然有效，首轮课程应保留调整余量。

## 11. 最高价值下一步

**组织一次真实教学环境中的“小型材质闭环试跑”。** 这是一个端到端验证活动，包含必要的教师预跑和少量代表性学生观察，而不是继续补写 TP 论证。

使用一个预制、干净、简单的物体，提供明确参考、有限可编辑起点和一份 AI/外部候选。要求学生完成一个自定的材质关系、接受一条局部修改要求、在换灯/视角后复核，并把关键关系迁移到陌生小样。初次操作有必要指导；独立判断仅在适当撤减提示后检查。

观察重点：

- 学生能否先说明想改什么和预计会发生什么；
- 是否靠反复试按钮，还是能定位依赖与错误层；
- 没有 AI 提供答案时还剩多少能力；
- 换载体后是否仍会判断；
- 教师实际需介入多少、文件/软件失败花费多少。

它能同时检验最关键的五个假设：持续项目是否合适、基础教学需要多深、AI 介入边界、软件负担、反馈容量。其信息增益高于再写一份看似严密的软件排名。

## 12. 技术教学材料的局部校正提醒

无需为此重做来源审计，但试跑材料应避免把现有文案直接复制成学生口诀：

- “数据贴图误标 sRGB = 粗糙度泛白”不是普适故障表现。官方支持 Non-Color 数据不应发生颜色转换；学生应理解输入数值被错误解释的机制，再根据具体观察判断，而非背一个固定视觉症状。[Blender Image Settings](https://docs.blender.org/manual/nb/4.5/editors/image/image_settings.html)
- Map Range 改变数值范围，不应被写成所有高光问题的标准修复；先确定输入、灯光与显示条件。
- 灰度 Metallic、反照率经验区间、图层是否存在，都不能单独代替对具体材料与交付任务的判断。

这些提醒服务于诊断任务的正确性，不提出新的课程单元。
